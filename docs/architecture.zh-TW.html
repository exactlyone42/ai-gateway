Agent Pool Gateway — 元件對照

控制面：提供請求流程需要的設定
元件作用主要程式提供給
憑證服務以 HMAC 雜湊驗證閘道金鑰，並處理快取與輪替。金鑰不是身分，而是用來解析完整的請求者身分。src/identity.rs驗證與身分解析
政策引擎合併 6 層政策：全域 → 使用者 → 裝置 → 用戶端 → Agent → 憑證 → 單次請求提示；請求提示不可突破上層硬性限制。src/policy.rs政策評估
配額引擎限制每分鐘請求與估算 token、時／日 token、併發請求、日／月成本；可按使用者、裝置、用戶端、Agent、模型及供應商分別限制。src/quota.rs准入控制
模型目錄由資料庫管理模型與品質別名（economy／standard／advanced／premium）。開發模式可用 ALLOWED_MODELS 環境變數。src/model_registry.rs模型路由
資料面：主要請求流程，由左往右
元件作用主要程式重點
協定轉接接受 Anthropic Messages、OpenAI Responses 與 Chat Completions，轉成一份供內部使用的標準請求。src/adapters/protocol.rs
src/routes/messages.rs
src/routes/responses.rs		多種用戶端格式 → 1 種內部格式
驗證與身分解析驗證閘道金鑰，解析出使用者、裝置、用戶端與 Agent；開發環境另有啟動用金鑰。src/auth.rs
src/identity.rs		一把金鑰對應完整身分鏈
政策評估產生本次有效政策，決定模型品質、工作類型、急迫度、預算與期限。src/services/request_policy.rs結果留作稽核，可回答「為何只給 standard」
准入控制進入佇列前檢查配額，明確決定接受、排隊、降級、換路或拒絕。src/services/admission.rs拒絕必須附原因，不可無聲丟棄
公平排程（WFQ）加權公平佇列、等待時間加權與保留容量；避免背景工作餓死，也保護互動請求；同時留意提示快取有效期。src/scheduler.rsWHEN：誰先執行；與路由分開
模型路由依健康、負載、成本與配額挑選供應商及模型；有斷路與冷卻機制，必要時自動降品質。src/routing.rs
src/model_registry.rs		WHERE：送到哪一家
供應商轉接把內部格式轉為各家格式，注入 Bearer 或 API Key；供應商憑證永不送給用戶端。src/adapters/provider.rs1 種內部格式 → 多家供應商格式
串流代理逐段轉送 SSE 回應，並把取消要求傳到上游；相同協定可直接轉送，避免重編碼。src/adapters/stream.rs
src/services/streaming.rs		回應沿原路反向返回
可觀測性與帳務：不阻擋主要請求
元件作用重點
用量帳本每次請求與 token 用量寫入 PostgreSQL；資料庫故障時先寫有容量上限的持久暫存，避免帳務遺失。精確計費依據，不是 Prometheus
OTLP 匯出用 OpenTelemetry 協定輸出指標、追蹤與遮蔽後的結構化日誌。不綁監控廠牌；內容不進日誌
稽核軌跡記錄控制面變更前後、操作人，以及身分、政策、金鑰生命週期變更。法遵需要

PostgreSQL保存身分、政策、金鑰雜湊、預算、用量帳本、設定版本與稽核；是帳務唯一正確來源。
OTel 後端開發預設 SigNoz，也可接 Grafana、Datadog 等相容後端；閘道只依賴 OTLP。
