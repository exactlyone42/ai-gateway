## 目的
部署一次不會砍掉全公司正在跑的 Claude Code session，也不會讓行程永遠退不掉。

## 完成判準
- [ ] **有上限的排空**：收到 SIGTERM 後停止收新請求、既有串流繼續，超過 `drain_timeout`
      才強制關閉。**不得**無上限等待——一條 SSE 不會自己結束。
- [ ] 排空期間 `/ready` 回非 200（讓負載平衡器移走），`/health` 仍 200（讓編排器別重啟它）。
- [ ] 被強制關閉的串流要留下記錄（哪些請求、進行到哪、用量估算），不是無聲消失。
- [ ] Request body 與 header 有大小上限，超過回 413 而不是把記憶體吃光。
- [ ] 所有上游呼叫有逾時；沒有任何一條路徑可以永久掛著。
- [ ] **多實例的併發與配額語意寫死在文件裡**：見下方「已知」的矛盾，二選一並記錄理由。
- [ ] 配額視窗的日／月邊界**定義時區**（含跨日跨月的邊界行為），寫進 `docs/request-policy.md`。
- [ ] **陰性對照 1**：起一條 10 分鐘的串流 → 送 SIGTERM → 串流必須繼續到結束或到
      `drain_timeout`；把排空邏輯拿掉，這條測試必須變紅。
- [ ] **陰性對照 2**：把 `drain_timeout` 設成 0 → 行程必須立刻退出且留下被砍串流的記錄。

## 已知
- 現況 `src/startup.rs:32` 的 `shutdown_signal()` 只等 `ctrl_c()`，之後交給 axum 的
  graceful shutdown。axum 會等 in-flight 請求結束——**SSE 串流不會自己結束**，
  所以現在的行為是「部署時要嘛永遠不退出、要嘛被外部砍掉」。兩種都不對。
- **文件互相矛盾，必須解掉**：`docs/architecture.md` 寫「至少兩個無狀態閘道實例」，
  而 `docs/work-breakdown.md` 的 W12 寫「第一版不做分散式計數器」。
  兩個實例 ＋ 各自記憶體計數 ＝ 所有併發上限與配額**實際上是兩倍**，而且沒有任何錯誤訊息。
  → 二選一：① 第一版明確單實例（文件改掉「至少兩個」）；
  ② 計數器放 PostgreSQL（多一次往返，要量）。**這個決定屬於本段落。**
- 這一段是反方審查抓出來的缺口：`grep -riE 'shutdown|drain|排空|滾動'` 在 `docs/` 與 `loops/`
  原本**零命中**。18 個段落沒有人擁有「帶著長命串流的行程生命週期」。

## 已確定不可行
- **靠 axum 的預設 graceful shutdown**：它等 in-flight 結束，而長命 SSE 沒有「結束」，
  等於無上限等待。必須自己管排空期限。
