## 目的

讓管理者用 email 辨識員工、用群組共用額度與權限，並能停用或恢復 Credential 而不刪除資料。

## 完成判準

- [x] User 支援 tenant 內唯一的可選 email，後台可建立、編輯與搜尋。
- [x] 可建立群組、加移成員，群組可綁政策與配額；個人預設優先，群組硬限制仍生效，同名個人額度符合條件時覆蓋群組額度。
- [x] 後台可啟用或停用 Credential，狀態變更立即使快取失效。
- [ ] 供應商權杖可綁群組：使用者自己有權杖就用自己的，否則用所屬群組的（S04，依賴 `gateway-completion` 的個人權杖設計，整合後才做）。
- [x] 格式、靜態檢查、後端與前端測試全過。
- [x] 陰性對照：重複 email、跨 tenant 成員、停用 Credential 與 user scope 覆蓋群組都必須被對應測試抓到。

## 已知

- 現有 users 表沒有 email/status；Credential 已有狀態機制，但後台未完整提供操作。
- 使用者於 2026-10-08 決定 email 可選但建議填寫。
- 使用者 2026-11-01 決定：同一個人的多個帳號（不同 email、角色）各建一個使用者，放進同一群組，權杖綁在群組，不新增「人」這一層，也不做一人多 email。群組不限制成員必須是同一個人，若把不同人放進掛有權杖的群組就等於共用席次，由管理者自律，文件須寫明。
- 不做群組繼承、巢狀群組、跨 tenant 群組或自動派發 Credential。
